## 为什么写技术博客

一个问题解决之后，最容易消失的往往是解决它的过程：起初做了什么假设，哪些尝试没有奏效，最后又是怎样找到线索的。把这些过程写下来，下一次遇到相似的问题，就能从已有的经验继续往前走。

博客可以是一份持续生长的笔记。文章不必从宏大的主题开始；一个报错、一段代码，甚至一个终于想明白的概念，都值得认真记录。

## 从一个小问题开始

可以先回答三个问题：

1. **遇到了什么？** 写清目标、环境和观察到的现象。
2. **怎样验证？** 留下最小示例、关键命令以及实际结果。
3. **得到了什么结论？** 说明结论适用的条件，也记录仍然不确定的部分。

例如，一篇关于脚本的短笔记，可以先从几行代码开始：

```python
from pathlib import Path

notes = Path("notes")
notes.mkdir(exist_ok=True)
print(f"笔记目录：{notes.resolve()}")
```

代码运行之后，再解释目录建立在哪里、重复运行会怎样，以及换一个工作目录会有什么变化。让读者能够重现，往往比写得复杂更有价值。

## 慢慢积累

给文章一个明确的标题，添加几个有用的标签，保留必要的参考链接。之后学到新的东西，再回来修订旧内容。

从今天的一篇小笔记开始，让遇到的问题逐渐变成可以回看的知识。
